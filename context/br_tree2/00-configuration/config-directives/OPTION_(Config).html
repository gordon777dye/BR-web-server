OPTION (config) — numbered feature toggles

The numbered OPTION feature toggles used in the BRConfig.sys file. Most may also be enabled at runtime with a CONFIG OPTION <n> statement, and most can be disabled with CONFIG OPTION <n> OFF (the last column notes which support the OFF form and from which release).

From within a BR program:

00010 EXECUTE "CONFIG OPTION 1"

Or set at BR32.exe launch by a line in BRConfig.sys:

OPTION 37

See also Option (disambiguation).

51 BR 5.01. Do not reuse deleted records. Without it (the default, or OPTION 51 OFF), a WRITE of a new record to an internal file takes a deleted record instead of adding one, the last deleted first, and that record's old contents are lost for good; with it on, new records are added at the end. A configuration that says OPTION 51 therefore gets no reuse. The file keeps its deleted records in a chain: a file made while records are reused has it from the start, and an existing file gets one, with every deleted record in it, the first time it is opened for OUTPUT or OUTIN while records are reused. An INPUT open changes nothing. VERSION(n, v) with a negative v keeps the version and empties the chain, so the next such open builds it again. Files that cannot have it simply grow: records shorter than 4 bytes, and record lengths whose header has no 4 bytes to spare (14 to 17). Keyed files: a record deleted while one of its indexes was not open leaves that index's key behind. In a file that reuses records, a keyed read therefore checks the record a key leads to: a deleted record, or one whose own key (built as WRITE builds it) is not that key, is treated as not there, so KEY= answers key not found and a sequential keyed read goes on to the next key. That holds for every engine reading the file, whatever its OPTION 51. A read through a Btree2 index checks the same way in every file, since an update stopped part way can leave a key behind there too; it also writes such a key to the index's .flaws file for INDEX ... REORG. Sharing: engines with the option on can use the file at the same time as engines that reuse records. They append, and a record they delete is reused once the file is next opened for output by an engine that reuses records, which links it into the chain. An earlier release can use the file before or after 5.01, but not while 5.01 has it open. Sessions sharing a file never drop a deleted record from its chain, a session closing the file while others write and delete included. COPY -D gives the copy an empty chain. Yes (4.18+)
