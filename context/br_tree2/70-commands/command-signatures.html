Command signatures

The argument shape of each BR console command, in one strict, machine-readable table. The prose BNF in the four command specs (editing, file-directory, information, program-management) is written for a reader, with -- commentary and informal brackets; this page restates it so a tool can match a command line against it. Nothing here is new behaviour. Every line cites the page it restates, and where a spec is vague the signature is deliberately loose (<word>, <text>) rather than guessed.

A command is runnable from code only through EXECUTE "<command-string>" (program-management), which is how brls meets them. Command names and abbreviations are not listed here: they come from BR's own table1k.

Notation

One command form per line; blank lines and -- comments are ignored. A line is the command's full name followed by its operands.

Element Meaning
WORD a keyword, written as in BR's tables. A qualifier from table2k may be abbreviated; any other word is matched whole. Case is ignored
'text' a literal word, such as ',' or '-p'
<kind> an operand, one word; see the kinds below
[ … ] optional
{ a | b } one of the alternatives; each alternative is a sequence
{ a | b }* any number of the alternatives, in any order

Words are separated by blanks or commas; a comma is a word of its own, and a quoted string is one word whatever it holds.

How a line is read

The signatures describe the operands; five rules describe how BR reads the line around them, and are applied to every command. Each was found by running the signatures over the QSMRP source, where production programs use forms the command specs do not write down, and each is backed by the tree where the tree speaks:

  • Options stand anywhere. A word that is a dash and letters or digits (-N, -D, -124) is an option, and is passed over wherever it falls and for any command. The specs list options per command (file-directory gives -D -F -N -P -S -V for the file commands, and INDEX gives -N), but QSMRP also writes -N after SORT, TYPE, DIR, MKDIR, PROTECT and PROC, and COPY a b -124 -d -n with the record length before other options, which BR accepts: it must be last only within one combined option word. The letters are not checked.
  • A comma is a blank. INDEX.md says parameters are separated by spaces or commas, and QSMRP writes PROTECT f Release and PROTECT f, Release alike. A ',' in a signature is therefore never required.
  • Keywords may be abbreviated to two letters or more (INDEX … Rep Dup -N). The commands have no table to say which prefixes are unique, so any prefix is accepted.
  • Case is ignored.
  • -? alone is the command help (BR 5.0). A line whose operands are exactly -? matches every command in BR's table except HELP and LINK: it lists the command's options and runs nothing (command-help). -? among other operands is not this, and is not an option either, since ? is neither a letter nor a digit: it is error 1006, whatever the command and wherever it stands after the command's keyword.
Operand Accepts
<int> digits only
<dashint> - followed by digits, as in RENUM -245 -365
<plusint> + followed by digits, as DIR +7 (entries changed 7 or more days ago)
<word> any one word, including a quoted string
<path> a file or directory name: any one word
<string> a quoted string
<text> one or more words, to the end of the line
<redirect> PRINT, or >file / >>file, the file attached or in the next word
<fromfile> <name: the < written against the name, as LIST <menu
<search> a quoted string, optionally preceded by ~
<flags:XYZ> - followed by one or more of the letters shown, as -AOLPWUCB
<status-topic> any one word; the topics BR knows are STATUS's table

Commands with no signature

These are in BR's command table and are not documented in this tree, so nothing is stated about their operands and a line using them is not checked past the name: CONFIG, FRE, HELP, LINK. (FRE is refused with error 1000; see file-directory.) LOGGING is documented in information but is not in BR's command table (table1k), so it has no signature here either.

Notes on the looser lines

  • LIST, DEL, GO, BREAK: the line-reference operand is <word> because the specs allow a line, a range, a label, n:clause and .n without giving one grammar for them. LIST takes up to two, since the spec says blank-separated line numbers may limit LIST <program and is silent on whether plain LIST does too.

  • RUN: the two spellings in the specs, RUN [<program>] [PROC] [STEP|TRACE] and RUN [STEP] [TRACE] [NORESTORE|RESTORE], are merged. PROC is an option, never a file name (run-proc).

  • SYSTEM: inside an EXECUTE string the operating-system command is the rest of the line, with no quotes of its own (EXECUTE "SYSTEM chmod 777 x"), so it is <text>.

  • PROC, SUBPROC: the specs name only the procedure (PROC {name|*name|ECHO|NOECHO}), but QSMRP writes SubProc * default.clr and Proc default.clr -N, so anything may follow.

  • INDEX: the work path is <word> and so also accepts a stray word that is not a keyword. The spec and INDEX.md disagree on how the work path is written ([<work-path>] against [-<work path>]).

  • STATUS: the spec lists topics with "…", so the topic is not checked.

  • DEBUG: the sub-options BR 5.0 documents are given their operands (AUTH, LISTEN, OBSERVE, SCREENLOG); the others in BR's table (LOG, CONNECT, DISCONNECT, CONSOLE, INTERNAL, PROFILE, STEP) are named and take <text>, since the release notes name them without giving their operands. DEBUG LISTEN takes a port and nothing after it: anything more is error 1006 (release notes 2.2).

  • DIR: the letters are the union of the 5.0 options (-T -S -R -A -L -N -B -W -C -M -P -O) and the 4.x ones kept under -O and OPTION 8 (adding -U). Which set applies depends on -O and OPTION 8, which a signature cannot see, so the letters are not checked (options stand anywhere). -ddd is an option word; +ddd is <plusint>.

  • AI: AI NEW starts a fresh conversation; any other text is the question. The assistant is not itself allowed to use it (error 4171).
