MSG

MSG("send",<string>) ! type a string into this session

The MSG internal function (without the dollar sign) is only available for Windows & CS versions. This should not be confused with Msg$. The first parameter is the action, and it is case insensitive. MSG has no effect on Unix or Linux terminal sessions, but works under Client / Server with Unix the same as WINDOWS.

MSG("kb") was removed in BR 5.0 and now raises 0412. Use MSG("send"), which takes the same arguments and behaves the same way. kb was only ever send behind a check that BR's window was in front; once send stopped being able to leave BR there was nothing for that check to do.

The actions

Action What it does
send type a string into this session — the rest of this page
sleeptime milliseconds between the keys send types; default 200
state the session's state
getpos getwpos getcpos read the pointer, window and caret positions
setpos setwpos setcpos move them — refused in a restricted session, 4154
lclick mclick rclick click — refused in a restricted session, 4154
getcb putcb read and write the clipboard
dump write the screen to a file
shot write a PNG of the screen to a file
restore restore the screen
loop the loop check
menu choose an item of BR's own menu by name, as a click on it would — see below; refused in a restricted session, 4154
harness open or close this session's assistant channel; 4173 while another session's channel is still waiting for its assistant
grant lend the keyboard to an assistant, or take it back
notify post a message an assistant can read
agentask agenttext agentline open a question for an assistant, and read what it delivered

A restricted session permits eighteen of these: state, getpos, getwpos, getcpos, getcb, putcb, loop, sleeptime, harness, grant, dump, shot, send, restore, notify, agentask, agenttext, agentline. The pointer actions, menu, and anything not in the table are refused with 4154, and each refusal is logged as a security event naming the action.

Where the keys go

send types into BR's own key buffer, and nowhere else. The keys go into the same ring a key pressed in BR's window lands in, so they reach this session only, whatever window has the focus, and no focus is needed at all.

This changed in BR 5.0. send used to emit operating-system keyboard input, which went to whichever window had the focus — so a program could type into another application, a command prompt, or another BR session. That is also why error 0413 existed, and why it is now retired.

MSG returns before the keys arrive. They are queued and fed to BR one at a time, sleeptime apart, while the program runs and reads them. So sleeptime paces what a person sees being typed, a string is no longer limited by the size of BR's key buffer, and a program must not expect every key to be there when the call returns.

Choosing a menu item

X = MSG("menu", "File|Open")               ! an item on the File menu
X = MSG("menu", "File|Recent|first.br")    ! an item on a submenu

MSG("menu", <path$>) chooses an item of the menu BR shows on its main window (DISPLAY MENU) as a click on it would: the program gets FKEY 98, and MENU$ returns the item's data, exactly as if the user had chosen it.

  • The path is the menu's labels, from the menu bar title down to the item, separated by |. Case is ignored, and so are the & accelerator marks and the shortcut text after a tab, so "File|Open" matches &File and &Open Ctrl-O. A bar title alone chooses nothing.
  • It is queued with the keys from send and the clicks, and delivered in that order while the program waits for input, sleeptime apart. MSG returns before it arrives.
  • It needs no mouse, no focus and no visible window. It works with BR's window covered, unfocused or off the screen.
  • A path that names no item is error 0415, and BR's log lists the paths the menu has.
  • Every choice is logged at the security level: MSG chose menu item <id>.

Why by name and not by position. lclick and the other clicks are refused over the menu: a drop-down menu is run by Windows itself, which only real mouse input on a visible window can drive. A program knows a menu by its labels anyway.

Error codes

*0412 Invalid Action Code — the first parameter is not an action. MSG("kb") raises this.

  • 0414 Wrong number of arguments passed
  • 0415 Some error that has err message
  • 0416 Not enough elements in dimensioned array
  • 0417 Dimensioned string length is not big enough
  • 0418 Unknown
  • 0419 Error in special char spec
  • 0440 MSG answer is not a number and the result variable is numeric
  • 4154 restricted session: this operation is not permitted
  • 4173 harness: another session's assistant channel is waiting for its assistant. Every session in an account publishes its token to one file, locked until an assistant claims it; try again once that channel is claimed or closes

*0413 Window Not On Top is retired. It was kb's refusal when BR was not the foreground window; nothing raises it now. The number stays reserved and is never reused.

Special Keystroke Values

Special characters are enclosed in pipes |, and are translated to BR's own key values the way key_scan.cpp translates a physical key. |CTRL+| and |SHIFT+| are tracked across the keys that follow them: |CTRL+| with a letter gives that control character, |SHIFT+| with a character gives its shifted form on the current keyboard layout (a to A, 1 to !), and either with a function, arrow or editing key gives that key's control or shifted variant.

A key that means nothing inside BR is dropped rather than sent anywhere: Alt, the Windows and Apps keys, and PrintScreen. They are accepted in the string and discarded, so LWIN, RWIN, APPS and SNAP in the table below do nothing on BR 5.0.

Examples

If you want to send ctrl+c, you must send the following string:

00010 MSG("send","|CTRL+|c|CTRL-|")

This says that you want depress the "CTRL" key, type "c", and then release "CTRL".

Example:

MSG("send","|CTRL+|p|CTRL-|")

Will input the CTRL-P character, which causes BR to perform a printscreen operation.

To send the pipe character specify |||.

MSG("sleeptime",milliseconds) specifies the number of milliseconds to wait before issuing each string and each control character (1000 = one second). The default is 200 (0.2 seconds).

The Alt advice that used to close this page no longer applies. It described how Windows interpreted Alt combinations when send went through the operating system, and read:

the ALT key needs to be depressed and released (ALT+ and ALT-) for every Alt-character specified - |alt+|m|alt-||alt+|b|alt-| works, |alt+|mb|alt-| fails.

BR 5.0 drops Alt rather than sending it, so neither form does anything now. Nothing replaces it: there is no Alt combination to send, because there is no longer an operating system in the path to interpret one.
