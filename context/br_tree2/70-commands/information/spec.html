Information & debugging commands

Inspecting state and debugging a running program: date/time, the command console, single-stepping, breakpoints, variable display, and logging. The HELP command, which shows br_tree topics in the browser or on the console, has its own page: HELP.

Syntax

DATE [<mm-dd-yy>|<mm/dd/yy>]   TIME [<hh:mm:ss>]   -- DA/TI; show/set session date & time (this terminal)
RUN [STEP] [TRACE] [NORESTORE|RESTORE]             -- step / trace execution (resume with GO → program-management)
BREAK [-p <prog>] { <line>[:<clause>] | <label>: | <var> | FN<name> | BEGIN } [OFF | '>'['>'] { <file> | <array$> }] [IF <cond>]   -- ST mode triggers
BREAK IF <cond> | BREAK IF OFF                      -- test <cond> after every line (5.0)
BREAK FILE <name> [OPEN|CLOSE] [OFF]                -- stop when the file is opened or closed (5.0)
BREAK ALL OFF                                       -- clear every breakpoint
DISPLAY [-p <prog>] { <var> | MAT <array> | ALL } [OFF | PRINT | '>'['>'] { <file> | <array$> }] [IF <cond>]
                                                    -- IF <cond> is last on BREAK and DISPLAY: it takes the rest of the line
DISPLAY FILE <name> [OPEN|CLOSE] [OFF] [PRINT]      -- report the file's OPENs and CLOSEs (5.0)
HELP <category> <topic>                             -- display documentation in the user's browser
LIST [<range>] [~]{ "<str>" | '<str>' }[…3x] [REPLACE "<new>"] [PRINT | '>'['>'] <file>]   -- search/replace
LOGGING <level> ',' <logfile> [',' UNATTENDED] [',' +CONSOLE]
STATUS [<topic>…] [-P] ['>'['>'] <file>]          -- ST; topics below
VERIFY                                               -- V; reports that verify is always on

Each of these commands lists its forms and options when given -? alone (STATUS -?, BR 5.0).

Semantics

  • DATE/TIME (commands, DA/TI) set or show the clock for this terminal, session only (per-workstation, lost on exit, no effect on the OS clock) — distinct from the DATE$/TIME$ functions that only read it. Quirk: DATE is set as mm-dd-yy (or mm/dd/yy) but reported as yy/mm/dd (legacy — programs normally use the function, not the command).
  • RUN STEP pauses after each action statement (Enter = next, GO = resume); TRACE prints line numbers as they execute; combine STEP TRACE. The fuller GO [STEP|TRACE] [.line] resume / temporary-breakpoint forms and Shift+F1–F5 stepping are in program-management.
  • BREAK drops a program into STEP mode when its target is hit: a line (must be an executable line — flow/assignment/I-O; not comments, DATA, or DIM), a label:, a changed variable/array/array-element (e.g. BREAK CUSTOMER$(6), as of 4.16), a FNname, or BEGIN (on entry). BREAK var also implies DISPLAY var. A redirection (> file, >> file, > A$, as for DISPLAY) does not change the break itself, but the line that implied display shows for a changed variable goes there instead of the screen (BREAK TOTAL >> TRACE$); with OFF it is refused (1006). The redirection must come before IF: IF takes the rest of the command as its condition, so BREAK TOTAL > T$ IF TOTAL>100 works, while in BREAK TOTAL IF TOTAL>100 > T$ the condition is TOTAL>100 > T$, which is not a valid expression (error 1026 when the break is reached). OFF clears one setting, ALL OFF clears all; -p <prog> masks which program/libraries it applies to. Conditional breakpoints (BR 5.0): IF <cond> after a target stops only when the condition is true, and BREAK IF <cond> with no target tests it after every line (BREAK IF OFF ends that). Before 5.0 the way was a stored IF A>B THEN EXECUTE "go step". BREAK FILE <name> stops when the file is opened or closed (OPEN or CLOSE for one of the two).
  • DISPLAY monitors variables as they change, printing line var new-value. It takes whole arrays (DISPLAY MAT CUSTOMER$) and single elements (DISPLAY CUSTOMER$(5)); -p <prog> masks programs; OFF stops it. IF <cond> (BR 5.0) reports a change only when the condition is true, and takes a variable of its own. The redirection must come before IF, which takes the rest of the command as its condition: DISPLAY TOTAL > T$ IF TOTAL>100, not DISPLAY TOTAL IF TOTAL>100 > T$. PRINT sends the lines to the printer and > file to a file (>> adds to it). > A$ sends them into a one-dimensional string array of the program the command is given in, one line to an element: > empties it first, >> keeps what it holds, and it is redimensioned as each line is written. A line longer than the elements makes them all that long, at the console and under EXECUTE alike; the one exception is an EXECUTE run under ON SOFLOW IGNORE, which cuts the line to the element length. Growing stops at SOFLOW-GROW MAX=. A display does not watch the array it fills: DISPLAY ALL > A$ leaves A$ out, and DISPLAY MAT A$ > A$ (or an element of it) is refused (1006). If the program or the array is gone when a line is written, the line goes to the screen. DISPLAY FILE <name> reports the file's OPENs and CLOSEs. In STEP/error mode, just typing a variable name prints its current value.
  • LIST "str" searches the program (and REPLACE "new" replaces): single quotes match case-insensitively, double quotes require an exact-case match, ~ negates a term, and up to three terms combine (all must match). Edit-while-running tip: change a line, then LIST … >file to record it; LOAD that source later. (Plain LIST <range> for display/editing is in editing.) Syntax: LIST [<from> [<to>]] [~]{"<str>"|'<str>'}[…3x] [REPLACE "<str>"] [CLAUSES] [{>[>]<file>|PRINT}]. A term with ~ must be absent from a line and one without it present, in any mix, up to three; the search runs over <from> to <to> (line numbers or labels) or the whole program. With REPLACE the lines are shown with the replacement made, but nothing is stored until you scroll back to each line and press Enter on it; to keep them all, redirect the output to a file and run it with PROC. -P shows one line at a time during a search or replace.
  • LOGGING writes a level-filtered log (0 major-error … 5 minor-event … 9 debugging). DEBUG_STR(level, str$) (function, BR 4.3+) emits str$ to the log (when level ≤ the active log level) and to the debugger, or to the command console if no debugger is attached and GUI is ON (levels >10 clamp to 10). In a restricted session it is how a program says what it is in its audit log, and the line is marked as the program's: it reads Program note: <str$>, control characters become spaces so it stays on one line, it is cut to 200 characters, and a level below 5 is logged at 5, so a note cannot pass for one of BR's own entries or errors. See LOGGING in a restricted session.
  • STATUS (ST) reports system state by topic; with none, the general status (program, active procedures, …). Topics, any of which may be abbreviated: ALL, ATTRIBUTES, BREAKPOINTS, COLORS, CONFIG, DATABASE, DIMS [LENGTHS [n]], ENCRYPTION, ENV [name], FILES [name], FONTS, KEYBOARD, LIBRARY, LOCKS [name], MEMORY, PRINTER, STACKS [RESET], SUBSTITUTE and USERS; a name after ENV, FILES or LOCKS narrows the report to it. -P pauses after each screenful and >file/>>file redirects. VERIFY (V) is kept for old procedures: in BR 5.0 it only reports Verify is always on. and checks nothing.
  • Console: the command console is the programming/run window (the bottom row is the command line); commands typed there run immediately, and you can inspect variables mid-run. MSG/BELL signal the operator.
  • MSG("send", str$) (function, Windows/CS only — not raw Unix/Linux terminals) types a string into this session: the keys go into BR's own key buffer, the same ring a key pressed in BR's window lands in, so they reach no other window and need no focus. Special keys go in pipes (MSG("send","|CTRL+|c|CTRL-|")), and MSG("sleeptime", ms) paces them in milliseconds (default 200 = 0.2s) — MSG returns before they arrive, since they are fed in one at a time while the program runs. MSG("kb") was removed in BR 5.0 and raises 0412; it was only send behind a foreground-window check, and error 0413 went with it. The full action list (twenty-five, of which a restricted session permits eighteen) and the key table: MSG.
  • PRINTER_LIST(MAT a$) (function) redims a$ to the active Windows printers (default first) and returns the count; the names double as OPEN "NAME=PRN:/…" targets (any matching substring suffices). Idiom + spooling tip: PRINTER_LIST.
  • PROCIN returns 1 when input is coming from a procedure file (else 0 from the screen) — useful to echo RUN PROC input. PROGRAM$ returns the full path (br_filename$) of the loaded .br/.wb program — handy in shared error routines. (Both are value-returning functions; they live here as console/debugging aids and are cross-linked from the function index.)
  • HELP <category> <topic> shows the br_tree topic for those words (HELP COMMANDS LIST, HELP LIBRARIES FILEIO), in the person's own web browser when br_tree2 is found and as pages on the console otherwise. HELP alone lists what it covers; Tab, Enter and the arrow keys then work together on that list, and Backspace at the end of a word takes the whole word and offers the words that fit there. F1 and Ctrl-Y show the topic for the word at the cursor. The browser tab, where the trees are found (CONFIG HELPTREE, HELPTREE2) and what the browser connects to: HELP.

Examples

RUN STEP TRACE
BREAK 1000           ! stop at line 1000;  BREAK TOTAL stops when TOTAL changes
DISPLAY MAT CUSTOMER$
LIST 'error'                 ! find error/ERROR/Error (case-insensitive)
LIST 60 300 '2,40,C 20,R' REPLACE "3,42,C 30,R"
LOGGING 9, trace.log
